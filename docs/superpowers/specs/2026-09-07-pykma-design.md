# pykma 설계

**작성일:** 2026-09-07
**저장소:** `alton15/pykma` (Public) · PyPI `pykma`
**한 줄:** 기상청 단기예보 API의 고통을 없앤 Python SDK, 그리고 그 위에 얹은 MCP 서버.

---

## 1. 왜 만드는가

### 목표

1. **남들이 쓴다** — PyPI 다운로드 수가 공개 지표로 남는다. 저장소에 배지로 건다.
2. **내가 쓴다** — MCP 층이 있어서 Claude에게 날씨를 물을 수 있다. 동기가 끊기지 않는다.
3. **포트폴리오** — "설계했다"가 아니라 "설계하고 배포했고 N명이 쓴다"가 적힌다.

### 자리가 비어 있다는 근거 (2026-09-07 확인)

| 확인한 것 | 결과 |
|---|---|
| PyPI `pykma` / `kma-api` / `pykma` / `weather-kr` / `kmapy` | 전부 **미등록** |
| GitHub `기상청 API language:Python` 최고 스타 | **5★** ([murianwind/kma_weather](https://github.com/murianwind/kma_weather), Home Assistant 컴포넌트) |
| 그 아래 | 전부 0~1★ 일회성 스크립트 |
| 비교군 — 한국 금융 데이터 | [`pykrx`](https://github.com/sharebook-kr/pykrx) **1,088★** |
| 비교군 — 한국 공공데이터 | [`PublicDataReader`](https://github.com/WooilJeong/PublicDataReader) **599★** |

수요는 증명돼 있는데(비교군 두 개), 기상청만 아무도 패키징하지 않았다.

수요의 직접 증거는 두 종류다.

- **모두가 같은 코드를 블로그에서 복붙한다.** 위경도→격자 변환 함수, `base_time` 계산,
  카테고리 코드 해석이 개인 블로그마다 재작성돼 있다.
  ([Dev Joon](https://han-joon-hyeok.github.io/posts/fetching-weather-data-from-public-data-center/),
  [velog](https://velog.io/@chaeri93/Django-%EA%B8%B0%EC%83%81%EC%B2%AD-%EB%8B%A8%EA%B8%B0%EC%98%88%EB%B3%B4-API-%ED%99%9C%EC%9A%A9%ED%95%98%EA%B8%B0))
- **응답을 다시 정리하는 저장소가 따로 생긴다.**
  [`kimsnake/kma-weather-collector`](https://github.com/kimsnake/kma-weather-collector)의 소개글은
  통째로 "시간대별 예보를 1개의 행으로 가로 확장(Pivot)하여 적재"다. 아래 고통 #3이 이것이다.

### 이 프로젝트가 하지 않는 약속

수익을 내지 않는다. 광고도, 유료 플랜도, 호스팅 서비스도 없다.

## 2. 없애는 고통 여섯 개

이 여섯 개가 라이브러리의 존재 이유 전부다. 이보다 적으면 만들 가치가 없고,
이보다 많으면 v1이 끝나지 않는다.

| # | 고통 | `pykma`가 하는 일 |
|---|---|---|
| 1 | **격자 변환.** API는 위경도를 안 받고 Lambert Conformal Conic 격자 `(nx, ny)`만 받는다 | `lat, lon`을 받아 내부에서 변환 |
| 2 | **`base_date` / `base_time` 계산.** 세 오퍼레이션의 발표 주기가 전부 다르고, 발표 직후엔 아직 자료가 없어 지연을 더해야 하며, 자정 근처에서 날짜가 하루 뒤로 넘어간다 | 호출 시각에서 **유효한 최신 발표**를 계산. 사용자는 시각을 만질 일이 없다 |
| 3 | **평평한 행 → 시간대.** 응답이 `fcstDate/fcstTime/category/fcstValue` 한 줄씩 수백 개로 온다. 쓰려면 시간대별로 pivot해야 한다 | 시간대별 객체 목록으로 묶어서 반환 |
| 4 | **카테고리 코드.** `TMP`/`SKY`/`PTY`/`POP`… 매번 표를 찾아본다. **오퍼레이션마다 코드가 다르다** — 초단기는 `T1H`/`RN1`, 단기예보는 `TMP`/`PCP` | 이름 있는 속성으로 노출. 오퍼레이션 차이를 라이브러리가 흡수 |
| 5 | **강수량 문자열 함정.** `PCP`/`SNO`가 숫자가 아니라 `"강수없음"`, `"1mm 미만"`, `"30.0~50.0mm"` 같은 **문자열**로 온다 | 숫자로 파싱한 값과 원문을 **둘 다** 준다 |
| 6 | **인증키와 가짜 200.** 포털이 인코딩·디코딩 두 형태의 키를 주는데, 인코딩된 쪽을 그대로 넘기면 `%`가 재인코딩돼 실패한다. 그리고 실패해도 HTTP는 200이고 본문만 XML 에러다 | 키 형태를 자동 판별. 본문 에러를 예외로 승격 |

## 3. 범위

### v1에 넣는 것

**단기예보 조회서비스 (`VilageFcstInfoService_2.0`) 하나.** 오퍼레이션 3개:

| 메서드 | 오퍼레이션 | 무엇 |
|---|---|---|
| `now()` | `getUltraSrtNcst` | 초단기실황 — 지금 실제 관측값 |
| `soon()` | `getUltraSrtFcst` | 초단기예보 — 향후 6시간 |
| `forecast()` | `getVilageFcst` | 단기예보 — 향후 3일 |

각 메서드는 동기·비동기 두 벌(`await kma.aforecast(...)`).

### v1에 **넣지 않는 것** (의도적)

- 중기예보, 기상특보, 생활기상지수 → v2 후보
- 기상청 API허브(`apihub.kma.go.kr`) → 별도 포털·별도 인증. 공공데이터포털 하나로 간다
- 주소 → 좌표 지오코딩 → 카카오/네이버 키가 또 필요해진다. 사용자가 위경도를 준다
- pandas 연동 → 무거운 의존성. 원하면 사용자가 `pd.DataFrame(rows)` 하면 된다
- 캐싱, 레이트리밋, 재시도 정책 → 실제 요구가 생기기 전엔 안 만든다

이 선이 "2주 안에 배포"를 가능하게 한다. `PublicDataReader`가 넓게 가서 599★를 얻은
자리에, `pykma`는 **좁고 깊게** 간다. 넓이로는 이길 수 없고 이길 필요도 없다.

## 4. 구조

```
pykma/
├── src/pykma/
│   ├── grid.py       위경도 ↔ 격자 (순수 함수, 의존성 0)
│   ├── clock.py      base_date/base_time 계산 (순수 함수, 의존성 0)
│   ├── codes.py      카테고리 코드 → 타입, 강수 문자열 파싱
│   ├── models.py     Observation / Forecast
│   ├── errors.py     예외 계층
│   └── client.py     httpx, sync + async
└── src/pykma_mcp/
    └── server.py     MCP 서버
```

### 단위별 책임

각 파일은 "무엇을 하나, 어떻게 쓰나, 무엇에 기대나" 세 질문에 답할 수 있어야 한다.

**`grid.py`** — 위경도와 기상청 격자 사이를 옮긴다. 기상청이 공개한 Lambert Conformal
Conic 파라미터가 상수로 박힌다. **의존성 없음.** 네트워크도, 다른 모듈도 안 쓴다.
`to_grid(lat, lon) -> Grid` / `to_latlon(nx, ny) -> tuple[float, float]`.

**`clock.py`** — "지금 이 오퍼레이션을 부르려면 `base_date`/`base_time`이 무엇이어야
하나"에 답한다. 오퍼레이션마다 발표 주기와 제공 지연이 다르다:

| 오퍼레이션 | 발표 | API 제공 |
|---|---|---|
| 초단기실황 | 매시 정시 | 발표 + 40분 |
| 초단기예보 | 매시 30분 | 발표 + 45분 |
| 단기예보 | 02·05·08·11·14·17·20·23시 | 발표 + 10분 |

호출 시각을 **인자로 받는다**(`now: datetime`). 내부에서 `datetime.now()`를 부르지
않는다 — 그래야 자정 넘김과 발표 직전/직후 경계를 네트워크 없이 전수 테스트할 수 있다.
**의존성 없음.**

위 표의 값은 공공데이터포털 **「단기예보 조회서비스 활용가이드」**를 정본으로 삼아
구현 시 대조한다. 표와 문서가 어긋나면 문서를 따르고 표를 고친다.

**`codes.py`** — 응답 코드와 값을 뜻으로 옮긴다. `SKY` 1/3/4, `PTY` 코드,
그리고 고통 #5의 강수 문자열 파싱. **모르는 코드는 버리지 않고 원문 그대로 통과시킨다**
— 기상청이 코드를 추가해도 라이브러리가 데이터를 삼키면 안 된다.
카테고리 코드 표 역시 위 활용가이드가 정본이다.

**`models.py`** — `Observation`(실황 한 개)과 `Forecast`(예보 한 시간대). 표준
`dataclass`. 이름 있는 속성으로 값을 주고, 파싱되지 않은 원본 행도 함께 들고 있다.

**`errors.py`** — `KMAError`를 뿌리로 한 계층. 최소한 인증 실패, 요청 한도 초과,
잘못된 파라미터를 구분한다. 고통 #6의 "본문 에러"가 여기로 올라온다.

**`client.py`** — 위 넷을 엮어 HTTP를 친다. 유일하게 네트워크를 아는 파일.

**`src/pykma_mcp/`** — 라이브러리를 도구 3개로 노출한다. `pykma`에만 의존하고
반대 방향은 없다. 설치는 `uvx pykma-mcp`, 실행 인자로 인증키를 받는다.

### 데이터 흐름

```
lat, lon ──grid.to_grid()──> nx, ny ─┐
                                     ├─> client ──HTTP──> 공공데이터포털
now      ──clock.base_for()──> date, time ─┘                    │
                                                                 ▼
사용자 <── models.Forecast[] <── 시간대별 묶기 <── codes.parse() ── 평평한 행[]
```

### 왜 이렇게 자르나

`grid.py`와 `clock.py`가 **의존성 0인 순수 함수**인 것이 설계의 핵심이다.

- 네트워크 없이 전수 테스트가 된다. 이 둘이 고통 #1·#2, 즉 사람들이 가장 많이 틀리는 곳이다.
- 남이 이 두 파일만 떼어 써도 된다. 실제로 대부분의 블로그 코드가 이 두 개만 필요로 한다.
- 나머지 모듈을 바꿔도 이 둘의 계약은 안 흔들린다.

## 5. 오류 처리

- **본문 에러를 예외로 승격한다.** HTTP 200 + XML 에러 본문은 조용히 넘어가면 안 된다.
  포털의 결과 코드를 읽어 해당하는 `KMAError` 하위 예외를 던진다.
- **예외 메시지에 인증키를 넣지 않는다.** 로그·스택트레이스로 키가 새는 가장 흔한 경로다.
- **파싱 실패는 그 필드만 버린다.** 한 카테고리의 값이 이상해도 나머지 시간대는 살린다.
  단, 조용히 넘기지 않고 원본 값을 객체에 남긴다.
- **인증키는 코드에 넣지 않는다.** `KMA(service_key=...)` 인자, 없으면 환경변수
  `KMA_SERVICE_KEY`. 저장소에는 이름만 있는 `.env.example`만 둔다.

## 6. 테스트

- **네트워크 금지.** 실제 응답을 한 번 녹화해 픽스처로 두고 그것으로만 테스트한다.
  CI가 기상청 서버 상태나 인증키에 기대면 안 된다.
- **`grid.py`는 기상청 공식 좌표표로 대조한다.** 기상청이 배포하는 지점별 격자 목록에서
  표본을 뽑아 변환 결과가 일치하는지 확인한다. 이것이 이 라이브러리의 가장 중요한 테스트다 —
  여기가 틀리면 나머지가 전부 옳아도 남의 동네 날씨를 준다.
- **`clock.py`는 경계를 전수로 친다.** 발표 1분 전 / 정각 / 제공 지연 직전·직후,
  그리고 자정 넘김(00:00~02:10 사이에 단기예보를 부르면 전날 23시 발표를 써야 한다).
- **고통 #5는 실제 문자열로 친다.** `"강수없음"`, `"1mm 미만"`, `"30.0~50.0mm"`,
  그리고 모르는 형식이 왔을 때 원문이 보존되는지.
- 커버리지 하한 90%.

## 7. 도구와 배포

`pykorail` 기여에서 익힌 것을 그대로 쓴다 — **uv, ruff, pytest**. Python 3.11+.
런타임 의존성은 `httpx` 하나(MCP 층은 별도 extra).

**CI (GitHub Actions):**
- PR·푸시: `ruff format` → `ruff check` → `ty check` → `pytest`
  (게이트 네 개 전부 통과해야 머지. `pykorail`의 CONTRIBUTING이 쓰는 것과 같은 조합이다)
- 태그 푸시: PyPI **Trusted Publishing**(OIDC)으로 배포.
  **API 토큰을 저장소 시크릿에 두지 않는다.**

**README에 거는 것:** PyPI 다운로드 배지, 버전 배지, 30초 안에 첫 호출까지 가는 예제.
검색으로 들어온 사람이 "이게 내 문제를 푸는 물건인가"를 3초 안에 판단할 수 있어야 한다.
README는 한국어·영어 둘 다 둔다 — 검색어가 한국어로 들어오고, 스타는 영어권에서도 온다.

## 8. 완료 기준

1. `pip install pykma` 로 설치되고, README의 예제가 그대로 돌아간다.
2. CI 초록. 커버리지 90% 이상.
3. 격자 변환이 기상청 공식 좌표표와 일치한다.
4. `uvx pykma-mcp` 로 Claude에 붙고, "내일 서울 비 와?"에 답한다.
5. PyPI 다운로드 배지가 README에 살아 있다.

**2주 안에 5번까지.** 이 숫자가 찍히기 전에는 다음 오픈소스(에이전트 도구)를 시작하지 않는다.

## 9. 이후

`pykma`는 3개짜리 오픈소스 트랙의 1번이다. 여기서 만든
**라이브러리 + MCP 서버 + PyPI Trusted Publishing + CI** 틀을 2번(에이전트 도구,
타겟 제한 없음)과 3번(게임)이 그대로 재사용한다. 각각 별도 스펙으로 간다.
